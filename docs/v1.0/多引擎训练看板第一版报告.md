# 多引擎训练看板第一版报告

## 1. 交付范围

第一版为 MMDetection 和官方 Ultralytics 训练提供统一的曲线查看入口。用户可以查看正在运行的任务，也可以回看已保存的训练结果。看板读取每次运行产生的结构化指标文件，不从自由文本日志猜测数值；它不负责启动训练或改变训练参数。

| 功能 | 第一版表现 |
| --- | --- |
| 训练任务看板 | 已开始的任务可在“模型训练/训练任务”的“操作 → 训练看板”打开；运行中每 4 秒自动刷新，也可手动刷新。 |
| 历史结果回看 | 在“结果查询”中使用结果行的“其他操作 → 训练看板”；该入口也适用于列表中的训练中任务。 |
| 指标图表 | 按损失、精度、学习率分组显示折线；展示引擎、运行状态、当前轮次或迭代以及指标文件更新时间。曲线支持图例和悬停查看数值。 |
| 引擎适配 | Ultralytics 读取本次运行的 `results.csv`；MMDetection 读取本次运行的 `vis_data/scalars.json`。 |
| 异常提示 | 尚未写入指标、指标文件暂不可读、Runner 请求失败、旧结果无法定位运行目录及自定义引擎无结构化指标时，界面显示相应提示。 |

## 2. 如何操作

1. 按项目 `README.md` 启动数据库、后端、前端和统一 Runner，并登录平台。看板请求由后端转发给 Runner，Runner 必须可用。
2. 在“模型训练/训练任务”中找到已经开始的任务，打开“操作 → 训练看板”。任务尚未开始时不显示该入口；用户只能访问自己的任务，管理员可访问全部任务。
3. 查看损失、精度和学习率曲线。运行中的任务每 4 秒自动刷新；点击右上角刷新按钮可立即重试。训练尚未产生指标文件时，等待引擎写入第一批指标。
4. 训练完成后进入“结果查询”，在对应结果的“其他操作 → 训练看板”回看本次运行曲线。历史结果只在保存了精确产物目录且文件仍存在时可回看。

图表只显示引擎实际写出的指标。某一组没有数据时，该组不出现；“精度”包括可识别的 mAP/AP 等验证指标，不能把所有曲线都理解为分类准确率。

## 3. 数据链路与边界

前端分别调用后端 `POST /trainMetrics/task` 或 `POST /trainMetrics/result`。后端检查任务/结果归属，按任务开始时间或结果保存的精确目录定位单次运行，再调用 Runner 的 `GET /api/runner/metrics`。Runner 解析指标文件并返回统一的曲线序列、横轴类型、当前步数和更新时间。单条曲线最多保留约 500 个绘图点，以控制长期训练时的页面负担。

自定义命令引擎当前没有统一的指标文件协议，因此只显示“未提供结构化训练指标”，不会解析任意日志。旧结果若缺少精确产物目录，会提示无法定位本次指标。指标文件被删除、训练环境未启动或 Runner 不可访问时，也无法展示对应曲线。第一版没有跨任务对比、指标持久化数据库、告警或导出图表功能。

## 4. 验证情况与后续验收

- 已通过 3 项 Runner 指标解析单元测试，覆盖 Ultralytics CSV 的未写完末行、MMDetection 标量记录及缺少指标时的空状态；Python 语法编译通过。
- 前端构建和后端编译通过。
- 选定的既有 Java 测试在初始化阶段受当前沙箱的本地端口监听与 JVM agent 限制，未得到测试结果；这不等同于业务测试通过。
- 尚未在有真实 MMDetection/Ultralytics 训练产物的环境中完成端到端联调。验收时应各运行一次短训练，确认曲线随写入更新、任务结束后停止自动刷新、结果页可回看同一次运行，并检查无指标与旧结果的提示。

本报告记录第一版功能与已完成验证，不代表真实训练已经通过验收。
