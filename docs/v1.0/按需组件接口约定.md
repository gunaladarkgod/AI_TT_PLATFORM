# 按需组件接口约定

前端“模型训练 → 组件管理”依赖后端提供工作区组件状态和补充命令。浏览器无法直接读取本机文件或执行终端命令，因此命令由后端根据服务端实际工作区生成，前端只展示和复制。

## 接口

`GET /api/workspace/components`

成功响应使用项目通用 `AjaxResult` 包装，`data` 为数组或 `{ "components": [...] }`。每个组件对象包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 稳定组件 ID，例如 `mmdet`、`ultralytics`、`small-object`、`knowledge-distillation` |
| `kind` | string | `engine` 或 `direction` |
| `name` | string | 前端显示名称 |
| `status` | string | `ready`、`missing`、`partial`；其他值显示为未知 |
| `path` 或 `relativePath` | string | 相对项目根目录的组件路径 |
| `downloadCommand` 或 `installCommand` | string | 可选；在项目根目录执行的补充命令 |
| `message` | string | 可选的状态详情或缺失项说明 |

组件 ID 和路径必须由服务端白名单决定，不接受前端任意路径或命令参数。若命令不存在，前端仍展示检测结果，但不提供补充操作。MMDetection、Ultralytics 和研究方向应分别报告状态；Runner 服务依赖已由现有 Runner 管理入口负责，不应混为引擎源码是否下载。
