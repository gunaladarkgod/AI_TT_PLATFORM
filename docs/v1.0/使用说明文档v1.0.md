# AI 训练平台使用与实验说明 v1.0

## 1. 平台用途与总流程

本平台用于把分散的原始目标检测数据集整理为可训练的数据集，并发起、跟踪和管理 MMDetection、官方 Ultralytics 和外部自定义训练任务。推荐按下面的顺序使用：

```text
导入原始数据集 → 创建任务并配置标签映射 → 导出中间实例数据集
→ 实例数据集预处理（含训测划分）→ 创建训练任务 → 发布训练 → 查看结果
```

### 引擎、基线与改进包的区别

平台按三层组织训练能力：

| 层级 | 包含内容 | 用户在训练时如何使用 |
| --- | --- | --- |
| 平台核心 | 前后端、数据集处理、统一 Runner、任务队列、引擎适配 | 不需要选择或修改；平台负责调度、日志、停止和产物管理 |
| 研究基线 | 某研究方向下可复现的起点，例如“官方 Ultralytics YOLO11n 小目标基线” | 选择研究方向和算法基线 |
| 改进包 | 在基线之上叠加的增强策略、模块或损失配置 | 按需勾选可兼容的改进包，并填写其动态参数 |

**引擎归属平台核心。** 引擎是“怎样执行训练”的通用能力，例如 MMDetection、官方 Ultralytics、外部自定义命令；基线是“在某个研究方向中，使用哪个引擎、版本、默认配置和数据格式”的研究定义。多个基线可以复用同一个引擎；改进包只能依附于某一个基线，不能脱离基线单独运行。

平台固定使用四个角色：`PlatformAdmin`、`BaselineMaintainer`、`ImprovementDeveloper`、`ExperimentOperator`。研究定义和源码权限仍通过 GitHub 协作与 PR 审查管理；前端已区分改进开发者和实验操作员，尚未在后端全面强制执行四角色授权。

实验操作员可以查询和预览已有数据集，选择已开放的基线与改进包、调整允许参数、创建和运行训练任务以及查看结果；数据集导入、修改、删除、预处理、脚本上传、标签映射、重新划分和结果维护入口不开放。改进开发者可以使用原有数据集准备与实验维护功能，改进包源码仍需通过 GitHub PR 审查。

点击顶部头像或用户下拉菜单中的“个人中心”，可以填写人员姓名、部门、手机号和个人简介，保存后刷新仍保留。右侧“我的权限”显示角色名称、角色代码和可用权限。角色不能在个人中心自行修改；账号类型对应关系为 1 平台管理员、2 基线维护者、3 实验操作员、4 改进开发者。

## 2. 启动后检查

1. 先启动 MySQL，再启动后端和前端。
2. 打开前端后，进入“模型训练”，确认右上角 Runner 状态为“正常”。
3. 没有安装 Redis 时，后端可使用内存降级模式启动；重启后登录令牌等临时缓存会丢失，但数据集和任务记录仍保存在 MySQL。
4. 首次启动若数据库不存在表结构，按根目录 README 的环境变量开启 Flyway 迁移一次。

## 3. 原始数据集

### 导入原则

“原始数据集”导入的是**目录地址和元数据记录**，不会把图片与标注复制到平台目录。因此：

- 原始数据集可以放在任意磁盘位置。
- 导入后请不要随意移动、改名或删除该目录、图片、标注文件；否则平台的预览、映射和导出可能无法识别。
- 删除原始数据集记录只删除平台中的登记信息，不会删除原始目录中的实际文件。

### 选择目录与标注

使用“导入外来数据集”选择数据集根目录后，先完成路径验证，再保存导入记录。Windows 环境会使用系统文件浏览器选择目录。平台预览会尝试识别 COCO JSON 与 txt 标注；常见的 txt 五列格式为：

```text
类别ID 中心点X 中心点Y 宽度 高度
```

这就是 YOLO 检测标注格式，四个坐标通常是相对图片宽高归一化后的值。点击“示例”可查看图片、类别与标注框。

## 4. 任务管理：标签映射与中间实例数据集

### 创建任务和映射

在“任务管理”中创建任务，选择一个或多个原始数据集，并把来源数据集的类别映射到任务统一类别。例如：

```text
origin_1 的 person  ┐
                    ├→ 任务类别 Person
origin_2 的 human   ┘
```

一个任务可以合并多个来源类别；只有被映射的类别才会进入导出结果。

### 导出状态

- 黄色“导出”：映射关系已配置，但尚未生成本地中间数据集。
- 黄色“更新”：映射关系在上次导出后发生变化，需要重新导出。
- 绿色“已最新”：本地中间数据集与当前映射关系一致。

点击“导出/更新”后，系统会筛选映射类别、合并来源、改为任务统一类别，并统一生成 COCO 格式标注。中间实例数据集固定存放在：

```text
data/instance_dataset_mid/{任务名称}/
├─ images/
└─ annotations/
   └─ instances.json
```

中间数据集不含训测划分。“清除导出数据集”会删除上述任务对应的中间实例数据集；之后任务状态会回到可导出状态。“打开路径”和“查看示例”仅在实际数据存在时可用。

## 5. 实例数据集预处理

“实例数据集预处理”只读取任务管理导出的**中间实例数据集**，不会把已预处理实例数据集再次作为输入。

选中一个或多个中间实例数据集后点击创建，在弹窗中配置增强脚本、增广脚本与训练集占比。两个脚本都可选择“不使用脚本”。系统会为每次预处理生成独立实例数据集，便于同一任务按不同脚本或不同训测比例进行对比，固定存放在：

```text
data/instance_dataset/{任务名称}/{实例数据集名称}/
```

创建时会先按“训练集占比”随机将原始图片及其对应标注划分到训练集、测试集，再分别执行所选脚本。这样同一原图及其增广副本不会同时进入两个集合，避免数据泄漏。可选择导出 COCO、YOLO 或同时保留两种格式；选择 YOLO 时会生成供 Ultralytics 使用的 `data.yaml`。完成后的目录为：

```text
images/train/
images/test/
annotations/train/
annotations/test/
```

在“实例数据集”中展开任务父行可看到该任务生成的所有实例数据集。子行可查看训测比例、训练集/测试集类别与数量、示例、打开路径、重新划分和删除；删除会同时删除记录与对应本地目录，请谨慎操作。

## 6. 模型训练

### 创建训练任务

选择可训练的实例数据集后创建训练任务。先选择训练引擎，再完成对应配置；引擎与模板信息来自项目文件，不依赖数据库中的模板记录。

#### MMDetection

- 算法模板：CNN、DETR、YOLO。
- 当前可用网络模板：Faster R-CNN、DETR、Deformable DETR、DINO、YOLOv3。

选择模板后，系统从 `engines/mmdet_run/myfiles/template` 读取对应 Python 配置，并在保存任务时生成：

```text
engines/mmdet_run/myfiles/modelcfg/{任务名称}/config.py
```

编辑已有 MMDet 任务时，模型类别和算法模板为固定信息，避免任务配置与历史训练结果不一致。

#### 官方 Ultralytics 与研究改进包

选择“官方 Ultralytics”后，依次完成：

1. 选择训练 Python，并点击“检查选中 Python”。当前平台校验 `ultralytics==8.4.115`。
2. 选择研究方向和该方向下的 Ultralytics 基线。
3. 选择已完成训测划分且已导出 YOLO 格式的实例数据集，填写该数据集的 `data.yaml`。
4. 可选勾选改进包。系统会自动显示基线和已选改进包共同声明的参数。
5. 填写预训练模型，例如 `yolo11n.pt`，再保存任务。

保存时平台会校验改进包是否属于所选基线、是否满足依赖、是否存在冲突或重复覆盖配置。任务会固定记录基线、改进包和最终参数；之后即使界面默认值改变，历史任务仍按保存时的配置运行。

#### 外部自定义命令

选择“外部自定义命令”后，填写训练 Python、执行目录、命令行和输出根目录。该模式用于项目外的既有训练脚本；平台只调度命令、管理日志和产物，不修改外部算法源码。

### 运行、停止与日志

- `mmdet` 使用生成的 MMDetection `config.py` 启动训练。
- `ultralytics` 使用任务保存的 Python、YOLO `data.yaml`、基线与改进包最终参数启动训练，不生成 MMDet `config.py`。
- `自定义` 使用固定模式，填写训练 Python、执行目录、命令行和工作目录等信息，由 Runner 执行指定命令。这类任务不使用 MMDet `config.py`。
- 点击“发布”后任务进入队列并由 Runner 发起训练。训练中可查看日志；界面会刷新最近耗时与日志中可识别的 Map 等指标。
- 停止训练会向 Runner 发出停止请求并更新任务状态。若实际训练已结束但仍显示训练中，请刷新 Runner 状态与最新日志，再检查 Runner 是否返回结束状态。

## 7. 结果查询与迁移

训练完成后可在“结果查询”查看训练记录、耗时、标签、备注、日志、配置快照和产物。点击一行可编辑结果名称、备注和标签；“其他操作”可查看日志、查看配置和打开路径。查看日志、打开路径需要 Runner 正常运行；自定义任务没有 MMDet `config.py` 时，查看配置会提示没有配置快照。

删除结果会同时删除对应的本地训练文件，应先确认权重和日志是否需要保留。训练运行产物位于：

```text
artifacts/mmdet_runs/
artifacts/custom/
artifacts/research/{研究方向}/{基线}/
```

整体复制项目目录到另一台设备后，中间实例数据集、实例数据集、模板与生成配置可继续使用。仍需准备 MySQL、Node、JDK、训练 Python 环境，并迁移数据库。外部原始数据集是路径引用，盘符或目录改变后需要重新导入或修正记录；新设备上也需要重新配置 `RUNNER_PYTHON`（如自动识别不到训练解释器）。
