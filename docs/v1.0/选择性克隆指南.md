# 选择性克隆指南

本文介绍如何从同一个 GitHub 仓库按需取得平台、训练引擎、研究基线和改进方案。无需拆分仓库，也无需额外下载工具。Windows 和 Linux 使用不同的终端，下面分别给出可复制的命令。

**验证状态：**本指南依据当前 `develop` 目录及清单编写，尚未完成选择性克隆后的平台启动和实际训练验证。基线是否可运行应以实际实现和测试结果为准；下载成功不代表训练成功。

## 1. 开始之前

- 安装 Git，并确认可以访问此私有仓库。执行 `git --version` 检查 Git；若提示不支持 `--sparse` 或 `sparse-checkout`，请升级 Git。
- 示例下载 `develop` 开发分支。`main` 是稳定分支，但其目录与基线可能不同，不能未经检查直接照搬 `develop` 的路径。
- 在有足够空间的位置新建工作区。示例使用不存在的 `AI_TT_PLATFORM_selective` 文件夹，不会覆盖已有项目。已有同名目录时，改成一个新名称。
- 准备 JDK、MySQL、Node.js、Runner Python、训练 Python、数据集和权重。代码克隆不包含本地环境、数据库记录、数据集和训练结果。启动方法见 [根目录 README](../../README.md) 和 [平台使用说明](使用说明文档v1.0.md)。
- 使用 SSH 地址需要提前配置 GitHub SSH 密钥；使用 HTTPS 地址需按 GitHub 提示完成认证。不要将凭据写入命令或文档。

本文有两步：**先克隆并选择平台公共内容，再按表格选择引擎和基线**。`git sparse-checkout add` 是增加目录，保留原先的选择；`set` 会替换当前选择，不要混淆。

## 3. Windows：PowerShell

### 3.1 克隆并选择平台

打开 **PowerShell**，进入保存项目的目录。例如保存到桌面：

```powershell
cd $HOME\Desktop
```

下面的 SSH 和 HTTPS 命令二选一，**不要重复执行两次**。HTTPS 在私有仓库需要登录：

```powershell
git clone --filter=blob:none --sparse --branch develop git@github.com:gunaladarkgod/AI_TT_PLATFORM.git AI_TT_PLATFORM_selective
```

或：

```powershell
git clone --filter=blob:none --sparse --branch develop https://github.com/gunaladarkgod/AI_TT_PLATFORM.git AI_TT_PLATFORM_selective
```

克隆成功后进入目录，选择公共组件：

```powershell
cd AI_TT_PLATFORM_selective
git sparse-checkout set --cone backend fronternd docs runner
git sparse-checkout list
```

这些组件仅是公共起点，还需执行下面对应的引擎和基线命令。根目录直接文件（包括 Windows 启动入口）也会检出。

### 3.2 选择引擎

使用 Ultralytics 基线时执行：

```powershell
git sparse-checkout add engines/yolo_run/ultralytics_runner
```

使用 MMDetection 基线时执行：

```powershell
git sparse-checkout add engines/mmdet_run
```

MMDetection 示例为了保留源码、模板及其依赖，选择整个引擎目录，下载可能较大；如两种引擎都需要，可以执行两条命令。Ultralytics Python 依赖需安装在**训练任务选择的 Python 环境**；MMDetection 模板配置还需在 **Runner 使用的 Python 环境**安装 `runner/requirements-mmdet.txt`。两个环境不必相同。

### 3.3 逐一选择基线

根据需要复制一条或多条；执行前先完成 3.2 中对应引擎的选择：

```powershell
# 小目标检测：Ultralytics YOLOv5s / YOLOv5m / YOLO11n
git sparse-checkout add research/small-object/ultralytics-yolov5s-v1
git sparse-checkout add research/small-object/ultralytics-yolov5m-v1
git sparse-checkout add research/small-object/ultralytics-yolo11n-v1

# 小目标检测：MMDetection Faster R-CNN R50
git sparse-checkout add research/small-object/mmdet-faster-rcnn-r50-v1

# 知识蒸馏方向：三个 Ultralytics 检测对照基线
git sparse-checkout add research/knowledge-distillation/ultralytics-yolov5s-v1
git sparse-checkout add research/knowledge-distillation/ultralytics-yolov5m-v1
git sparse-checkout add research/knowledge-distillation/ultralytics-yolo11n-v1

# 知识蒸馏方向：MMDetection DETR R50 协议示例
git sparse-checkout add research/knowledge-distillation/mmdet-detr-r50-v1
```

### 3.4 只选择指定改进包

3.3 中选择**整个基线目录**会包含该基线下的所有改进包。若只需要 YOLO11n 小目标增强方案，在尚未选择整个 YOLO11n 基线目录时，执行：

```powershell
git sparse-checkout add research/small-object/ultralytics-yolo11n-v1/improvements/small-object-augmentation-v1
```

另两个已登记的改进包可按同样方式选择（先选择 MMDetection 引擎；这两个改进包目前只是草稿/协议描述）：

```powershell
git sparse-checkout add research/small-object/mmdet-faster-rcnn-r50-v1/improvements/feature-fusion-v1
git sparse-checkout add research/knowledge-distillation/mmdet-detr-r50-v1/improvements/decoupled-kd-v1
```

Git 的 cone 模式会检出所选目录及其父目录的直接文件，因此这个例子也会取得方向和基线的 `direction.yaml`、`algorithm.yaml`。如后续基线增加 `src/`、配置或依赖目录，需要另外选择；若已选择整个基线目录，再加这一行不会排除其他改进包。

## 5. 下载后如何检查和增加方案

以下命令在两个系统的项目根目录均可使用：

```text
git sparse-checkout list
git status
git ls-tree -r --name-only HEAD research/
```

- `list` 查看本地已选择的目录；`status` 查看分支与未提交修改；`ls-tree` 查看当前提交中研究目录的文件名，不代表它们都已检出。
- 平台目前只扫描本地研究目录，未检出的基线和改进包不会出现在列表中。
- 有新方案时，先通过 `ls-tree` 或 GitHub 网页确认真实路径，再使用 `git sparse-checkout add <实际目录>`。如果方案依赖其他改进包或基线源码，也要添加对应目录，并检查清单中的依赖和冲突；Git 不会自动解析研究依赖。
- 要添加几个方案，可以多次执行 `add`；选择父目录会包含父目录下全部子目录。请先检查是否已选中更大的父目录。

## 6. 更新、恢复完整克隆及常见问题

正常协作先确认 `git status` 中没有未处理的改动，再按照 [GitHub 协作流程](GitHub协作流程.md) 更新 `develop`、创建功能分支并提交 PR。切换分支后目录可能变化，需要重新检查引擎和方案的路径。

需要恢复完整工作区时，先确认未提交修改及未跟踪文件已妥善保存，再执行：

```text
git sparse-checkout disable
```

此操作会检出其他文件，并可能继续下载较多内容。部分克隆仍会获取必要的提交和目录元数据；访问未下载的历史文件或增加目录可能触发联网。若服务器不支持过滤，Git 可能下载更多内容；实际节省量尚未测量。

克隆失败时先检查网络、GitHub 仓库权限和 SSH/HTTPS 认证。选择目录后找不到基线时，检查目标分支、拼写、引擎目录和 `git sparse-checkout list`；运行时缺文件、数据集或依赖时根据错误补齐，不要误认为下载了清单就能训练。旧版本 Runner 路径可能仍为 `engines/mmdet_run/mmdet_runner_srv`，应以目标分支的实际结构为准。

**权限提醒：**选择性克隆只是控制本地下载，不是 GitHub 权限隔离；有仓库读取权限的人仍可以下载其他代码。不要因本地看不到文件就认为它已从仓库删除，也不要在有未处理修改时随意缩小检出范围。
