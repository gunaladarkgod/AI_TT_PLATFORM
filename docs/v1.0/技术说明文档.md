# AI 训练平台技术说明文档

## 1. 架构与进程

| 模块 | 目录 | 默认端口 | 职责 |
| --- | --- | --- | --- |
| 前端 | `fronternd` | 5173（开发） | Vue 3 + Vite + Element Plus 管理界面 |
| 后端 | `backend` | 8081 | Spring Boot、MyBatis-Plus、数据集与任务 API |
| 数据库 | MySQL | 3306 | 用户、数据集登记、任务、训练结果等持久化数据 |
| 缓存 | Redis（可选） | 6379 | JWT 与临时缓存；可内存降级 |
| MMDet Runner | `mmdet_run/mmdet_runner_srv` | 8009 | FastAPI 训练、停止、日志、配置生成服务 |

开发模式下，Vite 将前端 `/develop/*` 代理到 `http://127.0.0.1:8081/*`。后端再通过 `sys.runner.train-url`（默认 `http://127.0.0.1:8009/api/runner/train`）调用 Python Runner。

## 2. 关键目录与路径策略

项目统一通过 `WorkspacePathUtil` 推导实际项目根目录，避免把某台电脑的绝对路径写进业务代码。

| 路径 | 说明 |
| --- | --- |
| `data/original_dataset` | 原始数据集的登记与辅助内容；外部导入的图片可在任意位置 |
| `data/instance_dataset_mid/{任务名称}` | 标签映射导出的中间实例数据集，COCO 标注，无训测划分 |
| `data/instance_dataset/{任务名称}/{实例数据集名称}` | 预处理完成的最终实例数据集 |
| `data/preprocess_scripts` | 上传的预处理/增强脚本 |
| `mmdet_run/myfiles/template` | 内置 MMDet 模板源文件 |
| `mmdet_run/myfiles/modelcfg/{任务名称}/config.py` | 任务保存时生成的最终训练配置 |
| `artifacts/mmdet_runs` | Runner 执行生成的日志、权重和结果文件 |

`APP_WORKSPACE_ROOT` 可显式指定项目根目录；未设置时，后端会从启动目录和代码位置向上搜索同时包含 `backend`、`fronternd`、`mmdet_run` 的目录。

## 3. 配置与启动维护

主要配置文件：[backend/src/main/resources/application.yml](../../backend/src/main/resources/application.yml)。

| 配置项/环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SERVER_PORT` | `8081` | 后端 HTTP 端口 |
| `DB_URL` | 本地 `ai_zm_master` | MySQL 连接串 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / `123456` | MySQL 账号 |
| `APP_FLYWAY_ENABLED` | `false` | 首次建库或升级时设为 `true` |
| `APP_FLYWAY_MODE` | `migrate` | 可用 `migrate`、`repair`、`disable` |
| `APP_REDIS_REQUIRED` | `true` | 无 Redis 时设为 `false`，避免启动等待 |
| `APP_REDIS_FALLBACK_MEMORY` | `false` | 无 Redis 时设为 `true`，启用内存缓存降级 |
| `RUNNER_AUTO_START` | `true` | 后端启动时自动拉起 Runner |
| `RUNNER_PYTHON` | 自动探测 | Runner 使用的 `python.exe` |
| `MMDET_REPO_ROOT` | 项目内 mmdetection | MMDetection 仓库路径 |
| `MMDET_WORK_ROOT` | `artifacts/mmdet_runs` | Runner 工作目录 |

数据库迁移脚本位于 `backend/src/main/resources/db/migration`，按 Flyway 版本号顺序执行。生产数据上不要执行 clean；项目配置已将 `clean-disabled` 固定为 `true`。

## 4. 数据集处理逻辑

原始数据集导入采用“登记外部路径”方式，不复制大量图片。预览、标签读取、导出时从登记路径读取真实图片和标注，因此外部路径失效会导致业务功能失效，但不会影响已生成的中间实例数据集和实例数据集。

`TaskDatasetDevController` 负责任务数据集管理。导出时依据映射规则筛选来源标注，合并同一任务类别，并生成标准 COCO 标注。输出固定为 `data/instance_dataset_mid/{任务名称}/images` 与 `annotations/instances.json`。

预处理输入只能是中间实例数据集；输出为最终实例数据集。每次创建生成独立子目录，避免覆盖历史预处理结果。训测划分通过实例数据集接口重新组织 images 与 annotations 的 train/test 目录。

## 5. 主要接口

| 分组 | 前缀 | 代表接口 |
| --- | --- | --- |
| 原始数据集 | `/original-dataset` | `GET /external`、`POST /external/import`、`POST /sample-random` |
| 任务数据集 | `/taskDatasetDev` | `POST /tasks`、`POST /tasks/mapping`、`POST /tasks/export`、`POST /tasks/clear`、`GET /tasks/preview` |
| 中间实例数据集 | `/instance-mid` | `GET /sourcedatasets` |
| 实例数据集 | `/instance` | `POST /instancedatasets`、`POST /instancedatasets/splitTrainTest`、`POST /instancedatasets/open-path` |
| 训练任务 | `/trainTask` | `POST /add`、`POST /update`、`POST /enqueue`、`POST /stop`、`POST /runner/log/latest` |
| Runner 管理 | `/api/runner` | `POST /health`、`POST /start`、`POST /dependencies/check` |
| 项目文档 | `/api/documentation` | `GET /usage-guide` |

新增接口时，应在对应 Controller 中定义清晰请求/响应结构，在 `fronternd/src/api/api.js` 中集中封装调用方法。涉及文件路径时，只允许服务端按 ID 或固定名称推导路径，不直接信任客户端的任意路径；删除文件前应确认目标在许可的数据根目录内。

## 6. MMDet Runner

Windows 启动脚本为 `mmdet_run/mmdet_runner_srv/start_runner.cmd`，Linux/macOS 使用 `start_runner.sh`。后端会依据操作系统优先选择相应脚本。

| Runner 接口 | 说明 |
| --- | --- |
| `GET /health` | 健康检查与活动训练状态 |
| `GET /api/config/templates` | 返回项目内模板目录中的可用模板 |
| `GET /api/config/template/defaults` | 读取模板默认配置值 |
| `POST /api/config/generate` | 基于模板生成任务 `config.py` |
| `GET /api/config/read` | 读取已生成任务配置 |
| `POST /api/runner/train` | 启动训练 |
| `POST /api/runner/stop` | 停止训练进程 |
| `GET /api/runner/log/latest` | 读取最新训练日志 |
| `POST /api/runner/result/delete` | 删除 Runner 本地结果 |

模型类别和模板选项由前端内置回退、后端内置默认项及 `mmdet_run/myfiles/template` 的实际文件共同决定，不依赖 `train_script`、`profile_train` 等数据库表中的模板记录。数据库仍保存训练任务、运行状态、备注和结果记录。

## 7. 故障排查

### 后端无法启动

1. 检查 MySQL 服务、账号、密码和 `ai_zm_master` 数据库。
2. 首次启动缺表时启用 `APP_FLYWAY_ENABLED=true` 和 `APP_FLYWAY_MODE=migrate`。
3. 未安装 Redis 时设置 `APP_REDIS_REQUIRED=false;APP_REDIS_FALLBACK_MEMORY=true`。

### Runner 不可用

1. 在模型训练页面点击“刷新/启动”，查看返回的失败原因。
2. 手动执行 `start_runner.cmd`，确认 Python 路径和 FastAPI、Uvicorn、MMEngine 依赖。
3. 访问 `http://127.0.0.1:8009/health`，确认端口没有被其他程序占用。
4. 查看 `mmdet_run/logs` 下的 Runner 日志。

### 数据集预览没有图片或标注

1. 原始数据集：确认登记路径仍存在，并包含图片和对应标注。
2. 任务管理：确认中间实例数据集存在于 `data/instance_dataset_mid/{任务名称}`，且有 `images` 和 `annotations/instances.json`。
3. 实例数据集：确认目录位于 `data/instance_dataset/{任务名称}/{实例数据集名称}`；训测划分后图片可能位于 `images/train`、`images/test`。
4. 从后端日志定位请求接口、解析的目录、图片目录和 COCO 标注文件是否存在。

## 8. 维护约定

- 不提交运行产物、大型数据集、模型权重和本地日志到代码仓库。
- 增加模板时，同时补齐模板文件、后端模板映射、Runner 模板目录和前端展示项；没有实际模板文件的选项应保持不可选。
- 修改路径规则时，优先修改 `WorkspacePathUtil`，不要在业务代码中新增用户电脑绝对路径。
- 数据库结构变更通过新的 Flyway 脚本完成，不修改已在其他环境执行过的历史迁移文件。
- 删除接口应明确“只删记录”还是“记录与本地文件都删”，并在前端进行二次确认。
